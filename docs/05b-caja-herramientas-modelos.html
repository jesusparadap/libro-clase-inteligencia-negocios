16  Caja de herramientas analíticas para decisiones

Pregunta empresarial: si describir los datos ya no es suficiente, ¿qué familia de modelos puede ayudarnos y qué evidencia necesitamos para confiar en ella?

Este capítulo organiza los materiales de las Partes 2, 3 y 4 como un portafolio de técnicas. No busca memorizar algoritmos ni demostrar matemáticamente cada método. La ruta es:

conocer → ejecutar → interpretar → evaluar → saber cuándo usar

16.1 1. Antes del modelo: ¿qué quiero decidir?

Un algoritmo no corrige una pregunta ambigua. Antes de elegirlo, completa:

Unidad de análisis:
Resultado o patrón de interés:
¿Existe una respuesta conocida (y)?
Momento en el que se hará la predicción:
Datos disponibles en ese momento:
Costo de un falso positivo:
Costo de un falso negativo:
Uso previsto del resultado:

16.2 2. Mapa general

Si quiero… Tipo de tarea Técnicas para explorar Producto
resumir qué ocurrió descriptiva medidas, tablas, gráficos perfil/KPI
estudiar asociación exploratoria/explicativa correlación, regresión relación estimada
estimar un número supervisada: regresión lineal, árboles, Random Forest valor predicho
predecir una categoría supervisada: clasificación logística, árbol, Random Forest clase/probabilidad
encontrar grupos sin etiqueta no supervisada K-means, medoides, jerárquico, DBSCAN cluster
resumir muchas variables no supervisada PCA componentes
detectar casos inusuales exploratoria/no supervisada IQR, Z-score, Isolation Forest, KDE alerta/anomalía
sugerir productos recomendación colaborativo, contenido, híbrido ranking
analizar texto NLP TF-IDF, LDA/NMF, embeddings, LLM temas/clases/similitud
estudiar patrones espaciales geográfica mapas, densidad, KDE zonas/patrones
El nombre del modelo importa menos que la correspondencia entre pregunta, variable objetivo, datos disponibles, métrica y decisión.

16.3 3. Supervisado y no supervisado

16.3.1 Aprendizaje supervisado

Existe una respuesta conocida y en los datos históricos.

  • Si y es numérica: regresión.
  • Si y es una categoría: clasificación.

El modelo aprende una relación aproximada X → y y se evalúa con observaciones que no utilizó para aprender.

16.3.2 Aprendizaje no supervisado

No existe una respuesta correcta conocida. Se buscan estructuras: grupos, componentes, densidades o anomalías.

Aquí no tiene sentido reportar accuracy contra una etiqueta inexistente. La evaluación combina criterios internos, estabilidad, utilidad empresarial e inspección humana.

16.3.3 Ejemplo de la diferencia

Pregunta ¿Hay respuesta conocida? Enfoque
¿Esta transacción terminará cancelada? sí: estado histórico clasificación
¿Qué valor de venta esperamos? sí: valor observado regresión
¿Qué perfiles de clientes aparecen? no clustering
¿Podemos resumir diez métricas en dos dimensiones? no PCA

16.4 4. Flujo mínimo de modelado

pregunta y uso
      ↓
unidad de análisis + objetivo
      ↓
datos disponibles al decidir
      ↓
separación entrenamiento/prueba
      ↓
preprocesamiento aprendido solo con entrenamiento
      ↓
modelo + línea base
      ↓
métrica coherente con el costo del error
      ↓
auditoría de errores, segmentos y limitaciones
      ↓
decisión, monitoreo o descarte

16.4.1 Entrenamiento y prueba

  • Entrenamiento: datos con los que el modelo aprende.
  • Prueba: datos reservados para simular observaciones no vistas.
  • Validación cruzada: repite particiones para estimar con mayor estabilidad.

Evaluar sobre los mismos datos de entrenamiento confunde memoria con capacidad de generalización.

16.4.2 Fuga de información

Hay data leakage cuando el modelo recibe información que no estaría disponible en el momento real de decidir, o cuando el conjunto de prueba influye en la preparación/entrenamiento.

Ejemplo: predecir cancelación usando un campo registrado después de la cancelación produciría un resultado artificialmente bueno e inútil.

16.4.3 Línea base

Antes de celebrar un modelo, compáralo con una regla simple:

  • regresión: predecir siempre la media/mediana;
  • clasificación: predecir siempre la clase mayoritaria;
  • series: repetir el último valor o patrón estacional.

Si el modelo no supera una base razonable, su complejidad no está justificada.

16.5 5. Correlación: detectar asociación, no decidir causalidad

La correlación responde si dos variables se mueven conjuntamente de una forma específica.

ventas[["descuento", "cantidad", "valor_venta"]].corr()
Medida Captura Precaución
Pearson asociación lineal extremos y no linealidad
Spearman asociación monotónica por rangos no captura toda relación posible

Una correlación alta no identifica por sí sola causa, mecanismo ni decisión óptima.

16.6 6. Regresión lineal simple y múltiple

16.6.1 Pregunta

¿Cuánto cambia o cuánto podemos estimar de una variable numérica?

En una regresión simple usamos una variable predictora. En una múltiple combinamos varias.

resultado numérico ≈ intercepto + efecto de X1 + efecto de X2 + ... + error

16.6.2 Dos propósitos que no deben confundirse

Propósito Prioridad Pregunta típica
Explicativo interpretar asociación y controlar variables pertinentes ¿cómo se relaciona X con y manteniendo otras variables?
Predictivo generalizar con el menor error posible ¿qué valor tendrá y para una observación nueva?

Un modelo muy interpretable no siempre es el mejor predictor; un predictor flexible no siempre explica bien.

16.6.3 Qué leer

  • signo y magnitud de coeficientes;
  • categoría de referencia para variables cualitativas;
  • error fuera de muestra;
  • residuos y casos de error grande;
  • estabilidad y plausibilidad.

16.6.4 Métricas

Métrica Lectura práctica Atención
MAE error absoluto promedio en la unidad de y todos los errores pesan linealmente
RMSE penaliza más los errores grandes sensible a extremos
R² proporción de variación explicada dentro del contexto evaluado no equivale a causalidad ni utilidad

Una métrica debe leerse contra la escala del negocio. Un MAE de 20.000 puede ser excelente o inaceptable según el uso.

16.6.5 Supuestos relevantes sin demostración

  • relación suficientemente bien representada;
  • observaciones pertinentes e independientes según el diseño;
  • residuos sin patrón grave;
  • ausencia de fuga;
  • predicción dentro de un rango respaldado por datos.

16.7 7. Clasificación

16.7.1 Pregunta

¿A qué categoría pertenece probablemente una observación?

Ejemplos: cancelada/completada, abandono/no abandono, fraude/no fraude, responder/no responder.

Un clasificador suele producir una probabilidad y después aplica un umbral para convertirla en clase. El umbral 0,50 es una convención, no una ley empresarial.

16.7.2 Matriz de confusión

Real positiva Real negativa
Predicción positiva verdadero positivo falso positivo
Predicción negativa falso negativo verdadero negativo

Para NovaRetail:

  • falso positivo: activar una intervención para una venta que no se cancelaría;
  • falso negativo: no intervenir en una venta que terminará cancelada.

La mejor métrica depende de cuál error cuesta más.

16.7.3 Métricas principales

Métrica Pregunta
Accuracy ¿qué proporción total clasificamos correctamente?
Precision de las alertas, ¿cuántas eran realmente positivas?
Recall/sensibilidad de los positivos reales, ¿cuántos detectamos?
F1 ¿cómo equilibramos precision y recall?
ROC-AUC ¿qué tan bien ordena el modelo positivos frente a negativos en distintos umbrales?

Con una clase rara, una accuracy alta puede ser trivial. Si solo 5 % cancela, predecir “no cancela” siempre logra 95 % y no detecta ningún caso.

16.8 8. Regresión logística

La regresión logística modela la probabilidad de una clase. Es una primera opción valiosa porque:

  • genera probabilidades;
  • permite una línea base interpretable;
  • funciona bien cuando la relación es razonablemente simple;
  • facilita discutir signo, magnitud y umbral.

Precaución: los coeficientes no son cambios directos de probabilidad; para audiencias ejecutivas conviene mostrar probabilidades predichas o efectos marginales, además del desempeño.

16.9 9. Árbol de decisión

Un árbol aprende reglas sucesivas:

                  ¿descuento > 15 %?
                    /             \
                  sí               no
                 /                  \
          ¿canal = Web?        probabilidad menor

16.9.1 Fortalezas

  • representación visual intuitiva;
  • relaciones no lineales e interacciones;
  • reglas accionables.

16.9.2 Riesgos

  • un árbol profundo memoriza ruido;
  • pequeños cambios pueden producir otra estructura;
  • “importancia” no equivale a efecto causal;
  • una regla aprendida no es política automática.

La profundidad y otros parámetros controlan la flexibilidad. Muy poca flexibilidad produce sesgo; demasiada produce sobreajuste.

16.10 10. Random Forest y ensambles

Random Forest combina muchos árboles construidos con muestras y subconjuntos de variables. La agregación suele mejorar estabilidad y predicción respecto a un solo árbol.

16.10.1 Intercambio central

Un árbol Random Forest
más fácil de explicar suele predecir mejor
más inestable más estable
reglas visibles decisión agregada menos transparente

La importancia de variables indica cuánto ayuda una variable al modelo bajo una definición concreta. No afirma que cambiar esa variable cause el resultado.

16.11 11. Clustering: encontrar grupos sin etiquetas

16.11.1 Pregunta

¿Existen perfiles de observaciones con características similares?

En NovaRetail podemos construir una tabla por cliente:

cliente | compras | gasto_total | ticket_promedio | descuento_promedio

Después estandarizamos porque gasto en pesos y número de compras tienen escalas distintas.

16.11.2 K-means

  • representa cada grupo por un centroide;
  • requiere elegir k;
  • favorece grupos aproximadamente compactos;
  • es sensible a escala e inicialización.

El algoritmo entrega cluster 0, cluster 1… El analista inspecciona perfiles y propone nombres. “Premium” no sale automáticamente del algoritmo.

16.11.3 Medoides

Se parece a K-means, pero el centro del grupo es una observación real. Puede ser más robusto ante extremos y admite otras medidas de distancia.

16.11.4 Jerárquico

Construye una jerarquía y la representa con un dendrograma. Es útil para explorar grupos anidados y discutir diferentes niveles de corte.

16.11.5 DBSCAN

Forma grupos a partir de zonas densas y puede marcar ruido. No exige k, pero requiere parámetros de vecindad/densidad y puede fallar cuando las densidades cambian mucho.

16.11.6 Evaluar sin “respuesta correcta”

  • cohesión/separación, por ejemplo silhouette;
  • estabilidad ante muestras y parámetros;
  • tamaño suficiente de los grupos;
  • interpretabilidad del perfil;
  • utilidad para una acción diferenciada;
  • revisión de si el algoritmo solo reprodujo escala o una variable dominante.
Advertencia

Segmentar personas puede amplificar sesgos o producir acciones injustas. Las variables, nombres y usos deben revisarse ética y operacionalmente.

16.12 12. PCA: reducir complejidad

16.12.1 Pregunta

¿Podemos resumir muchas variables correlacionadas en menos dimensiones conservando buena parte de su variación?

PCA construye componentes como combinaciones de las variables originales.

16.12.2 Qué interpretar

  • varianza explicada: cuánta información resume cada componente;
  • cargas: qué variables contribuyen y en qué dirección;
  • scores: posición de cada observación en los componentes.

16.12.3 Precauciones

  • estandariza cuando las unidades difieren;
  • el componente maximiza varianza, no relevancia empresarial;
  • el nombre del componente lo propone el analista;
  • reducir dimensión puede sacrificar interpretación.

PCA sirve para visualización, compresión, preprocesamiento y exploración; no es automáticamente un modelo predictivo.

16.13 13. Detección de anomalías

16.13.1 IQR

Detecta extremos univariados con una regla transparente.

16.13.2 Isolation Forest

Aísla observaciones mediante particiones aleatorias; las combinaciones inusuales suelen aislarse con menos divisiones.

Una anomalía significa:

caso que merece investigación

No significa automáticamente fraude, error o cliente indeseable.

Evalúa utilidad mediante revisión de casos, tasa de alertas, falsos positivos, estabilidad y costo de investigación.

Los materiales de la Parte 4 también incluyen familias que no se desarrollan completas en las siete horas presenciales:

Familia Pregunta Cuándo continuar
Sistemas de recomendación ¿qué opción ordenar para cada usuario? interacciones usuario–producto o atributos de contenido
NLP/LDA ¿qué patrones aparecen en texto? corpus suficiente y validación humana
Datos geográficos/KDE ¿dónde se concentran eventos? coordenadas válidas, escala y contexto espacial

16.15 15. Quick Reference · escoger y auditar

Familia Requiere y Salida Métrica inicial Pregunta de auditoría
Regresión sí, numérica número MAE/RMSE + base ¿el error es aceptable en la unidad del negocio?
Logística sí, categórica probabilidad recall/precision/AUC ¿el umbral refleja el costo del error?
Árbol sí regla/clase/número fuera de muestra ¿está sobreajustado?
Random Forest sí clase/número fuera de muestra ¿la mejora compensa menor transparencia?
K-means no cluster silhouette + estabilidad ¿los grupos son accionables o solo matemáticos?
Jerárquico no dendrograma estabilidad/cortes ¿qué nivel de agrupación tiene sentido?
PCA no componentes varianza explicada ¿qué información e interpretación se perdió?
Isolation Forest no anomalía/score revisión de alertas ¿qué proporción de alertas merece acción?

16.17 17. IA como copiloto, no como juez

La IA puede ayudar a proponer código, revisar un pipeline, explicar una métrica o identificar riesgos. El flujo responsable es:

  1. plantea la pregunta;
  2. entrega únicamente variables reales;
  3. pide una línea base y una separación correcta;
  4. ejecuta en Colab;
  5. revisa salidas y errores;
  6. audita supuestos, fuga y lenguaje;
  7. documenta cambios.

Prompt reutilizable:

CONTEXTO
Tengo una tabla donde una fila representa [unidad]. Quiero apoyar la decisión [decisión]. La variable objetivo es [y] y solo dispongo de [X] en el momento de decidir.

TAREA
Propón una línea base y un pipeline reproducible. Separa entrenamiento y prueba antes de aprender transformaciones. Incluye una métrica coherente con [costo del error] y una auditoría por segmentos.

FORMATO
1. Supuestos. 2. Código comentado. 3. Pruebas de validación. 4. Guía de interpretación. 5. Riesgos.

RESTRICCIONES
No inventes columnas. No uses información posterior al resultado. No interpretes asociación o importancia como causalidad. Señala cualquier dato que falte.

16.19 19. Transferencia a tu proyecto

Elige una pregunta, no un algoritmo. Después completa la ficha mínima y decide:

  • si realmente existe una variable objetivo;
  • si la tarea es descriptiva, supervisada o no supervisada;
  • qué datos estarán disponibles cuando se use el resultado;
  • qué línea base corresponde;
  • qué error importa;
  • quién podría actuar;
  • qué riesgo haría preferible no desplegar el modelo.
