9  Manipulación de datos: de la pregunta al KPI

9.1 Propósito

La secuencia será: pregunta → tabla → verificación → interpretación → visualización.

9.2 Setup

library(tidyverse)
ventas <- read_csv("data/ventas.csv")
glimpse(ventas)

9.3 filter() — ¿qué observaciones?

ventas |>
  filter(estado=="Completada", region=="Caribe")

9.4 select() — ¿qué variables?

ventas |>
  select(fecha,region,canal,categoria,descuento,valor_venta)

9.5 mutate() — crear información

ventas <- ventas |>
  mutate(
    valor_por_unidad=valor_venta/cantidad,
    tiene_descuento=descuento>0
  )

9.6 arrange() — inspeccionar extremos

ventas |>
  arrange(desc(valor_venta)) |>
  select(id_venta,region,canal,categoria,valor_venta) |>
  head(10)

Un extremo merece investigación; no se convierte automáticamente en error.

9.7 group_by() + summarise() — cambiar granularidad

kpi_region <- ventas |>
  filter(estado=="Completada") |>
  group_by(region) |>
  summarise(
    ventas=sum(valor_venta,na.rm=TRUE),
    transacciones=n_distinct(id_venta),
    clientes=n_distinct(id_cliente),
    .groups="drop"
  ) |>
  mutate(
    ticket_promedio=ventas/transacciones,
    ventas_por_cliente=ventas/clientes
  )
Después del resumen, una fila representa una región, no una transacción.

9.8 Primero tabla, después gráfico

kpi_region |> arrange(desc(ventas))

Solo después:

ggplot(kpi_region,aes(x=reorder(region,ventas),y=ventas))+
  geom_col()+coord_flip()+
  labs(title="Ventas completadas por región",x=NULL,y="Ventas")

9.9 Una métrica no cuenta toda la historia

Compara ventas, clientes, ticket y ventas por cliente. La región líder puede cambiar según la pregunta.

9.10 Reto

Construye KPI por categoría: ventas, transacciones, clientes, unidades, descuento promedio y ticket. Escribe:

  1. una descripción sustentada;
  2. una hipótesis que requiera evidencia adicional.

9.11 IA como auditor

“Explica la granularidad antes y después del summarise(). Señala KPI con denominador discutible y qué prueba ejecutarías.”
